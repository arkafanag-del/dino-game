# Безопасность API

## Что закрыто

Ранее API доверял клиенту и позволял накручивать монеты. Теперь:

- все игровые эндпоинты требуют `Authorization: Bearer <token>`;
- имя в теле запроса должно совпадать с именем из токена;
- `/api/player/save` больше **не увеличивает** баланс: старый параметр `coins`
  принимается только для уменьшения баланса (учёт трат), и только если
  `LEGACY_SAVE_ENABLED=1`;
- скины нельзя открыть через сохранение профиля — только через магазин или казино;
- награда за забег ограничена реальным временем забега;
- рекорд в лидерборде обновляется только в `/api/run/finish` по проверенному
  сервером счёту, `/api/score` больше не принимает произвольный рекорд;
- урон мировому боссу можно наносить только в активном серверном забеге,
  урон ограничен временем забега (`MAX_WORLD_BOSS_DPS`);
- награда босса требует минимальный урон (`MIN_WORLD_BOSS_DAMAGE_FOR_REWARD`)
  и выдаётся один раз;
- добавлены лимиты запросов (по IP и по игроку), ограничение размера тела
  запроса и ограничение CORS.

## Аутентификация

| Метод | Эндпоинт | Назначение |
|---|---|---|
| POST | `/api/auth/register` | `{"name": "...", "password": "..."}` → токен |
| POST | `/api/auth/login` | `{"name": "...", "password": "..."}` → токен |
| POST | `/api/auth/logout` | инвалидирует текущий токен |
| GET | `/api/auth/me` | профиль текущего игрока |

Пароли хранятся как PBKDF2-SHA256 (200 000 итераций по умолчанию).
В БД хранится только SHA-256 от токена сессии, поэтому утечка базы не даёт
готовых bearer-токенов.

Все игровые запросы отправляют заголовок:

```
Authorization: Bearer <token>
```

## Старые аккаунты

У аккаунтов, созданных до появления паролей, `password_hash` пустой,
поэтому войти они не могут. Посмотреть таких игроков и задать пароль:

```bash
python set_password.py --list
python set_password.py "ИмяИгрока"
```

Скрипт попросит пароль скрыто. Для автоматизации:

```bash
echo "новый-пароль" | python set_password.py "ИмяИгрока" --stdin
```

Заменить уже существующий пароль можно через `--force`.
После смены пароля все сессии этого игрока удаляются.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DB_FILE` | `/data/dino.db` или `./dino.db` | путь к SQLite |
| `LEGACY_SAVE_ENABLED` | `0` | разрешить старому клиенту уменьшать баланс через `/api/player/save` |
| `SESSION_TTL_SECONDS` | 30 дней | срок жизни токена |
| `PASSWORD_ITERATIONS` | `200000` | итерации PBKDF2 (минимум 100000) |
| `MAX_BODY_BYTES` | `16384` | максимальный размер JSON-тела |
| `MIN_RUN_SECONDS` | `10` | минимальная длительность забега |
| `MAX_COINS_PER_SECOND` | `20` | потолок награды за забег |
| `MAX_SCORE_PER_SECOND` | `12` | потолок счёта за забег |
| `MAX_WORLD_BOSS_DPS` | `100` | потолок урона боссу в секунду забега |
| `MIN_WORLD_BOSS_DAMAGE_FOR_REWARD` | `1000` | минимальный урон для награды |
| `RATE_LIMIT_WINDOW` | `10` | окно лимита запросов, секунды |
| `RATE_LIMIT_MAX_REQUESTS` | `5` | запросов на IP за окно (на каждый scope) |
| `RATE_LIMIT_MAX_KEYS` | `50000` | максимум ключей в памяти rate limiter |
| `RATE_LIMIT_PRUNE_INTERVAL` | `60` | как часто чистить истёкшие ключи, секунды |
| `TRUST_PROXY_HEADERS` | `0` | доверять `Fly-Client-IP` / `X-Forwarded-For` |
| `CORS_ORIGINS` | `*` | список origin через запятую |

Для Fly.io в `fly.toml` уже включены `TRUST_PROXY_HEADERS=1`,
`LEGACY_SAVE_ENABLED=0`, `MIN_RUN_SECONDS=10` и лимиты босса.

## Изменения контракта API (breaking)

- Все игровые эндпоинты требуют bearer-токен.
- `POST /api/world-boss/damage` теперь требует `run_id` активного забега.
- `GET /api/world-boss` больше не принимает `?name=`; игрок берётся из токена.
- `POST /api/player/save` игнорирует `unlocked_skins` и не увеличивает `coins`.
- `POST /api/score` не обновляет рекорд; счёт приходит из `/api/run/finish`.
- Новый поток игры: `/api/run/start` → игра → `/api/run/finish`
  (`run_id`, `score`, `coins_earned`, `quests_completed`).

Старый фронтенд из соседней папки (`../script.js`) ещё не обновлён под этот
контракт: он не отправляет токен, не вызывает `/api/run/start` и
`/api/run/finish`, не передаёт `run_id` боссу и пытается сохранять абсолютный
баланс. Без обновления клиента серверные монеты, рекорды и босс работать не будут.

## Проверки

```bash
python -m py_compile main.py db.py set_password.py
python tests/security_check.py
python tests/migration_check.py
```

`security_check.py` проверяет 20 сценариев: отсутствие авторизации,
подмену имени, накрутку монет, бесплатные скины, мгновенный забег,
подделку рекорда, урон и награду босса, размер тела, logout, логин,
минимальный урон, rate limit, сохранение выбранного скина, «оверкилл»
босса, ограничение памяти rate limiter и валидацию итераций PBKDF2.
`migration_check.py` проверяет миграцию старой БД без потери игроков и
рекордов, а также создание индексов сессий.

## Исправленные баги (после первичного аудита)

- Rate limiter больше не растёт бесконечно: истёкшие записи удаляются,
  число ключей ограничено `RATE_LIMIT_MAX_KEYS`.
- `POST /api/player/save` без поля `selected_skin` больше не сбрасывает
  выбранный скин на `default`.
- `PASSWORD_ITERATIONS` ограничивается сверху (`MAX_PASSWORD_ITERATIONS`),
  чтобы конфиг не создавал хэши, которые потом невозможно проверить.
- POST без тела и без `Content-Length` (например, logout по HTTP/2) больше
  не отклоняется; chunked-тело без `Content-Length` по-прежнему запрещено.
- «Оверкилл» мирового босса больше не раздувает недельный урон: в зачёт
  идёт только реально снятое HP.
- В журнал `transactions` пишется фактически начисленная сумма, а не
  запрошенная (важно у лимита `MAX_COINS`).
- Добавлен индекс `sessions(expires_at)` для быстрой очистки сессий.
- `set_password.py` больше не обрезает имя до 20 символов, чтобы опечатка
  не сменила пароль другому игроку.
- `.dockerignore` / `.gitignore` теперь исключают SQLite WAL/SHM-файлы и
  `opencode.json` (в нём лежит API-ключ).

## Что осталось за рамками

- Старые накрученные балансы и рекорды не сбрасываются автоматически.
  При необходимости их можно проверить по таблице `transactions`.
- Лимиты запросов хранятся в памяти процесса. При нескольких инстансах
  приложения нужен общий store (Redis).
- Docker-образ в этом окружении не собирался (Docker недоступен).
- Фронтенд нужно обновить отдельно под новую авторизацию и серверные забеги.
- ДНК и шлейфы по-прежнему хранятся только на клиенте: сервер фиксирует
  выигрыш казино в журнале, но не может проверить их расход. Монеты, скины,
  рекорды и урон босса — серверные.
- `opencode.json` содержит API-ключ. Он добавлен в `.gitignore`, но ключ
  стоит перевыпустить, если файл уже куда-то попадал.
